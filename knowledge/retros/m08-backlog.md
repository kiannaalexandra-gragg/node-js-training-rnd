## [BACKLOG] Not fixed

- **`Dates/` leaves a task behind if a run stops part-way.** Its requests share one task made by `Dates/01` and deleted by `Dates/07`. `Listing/` has the same shape. A failed run leaves a "Date boundaries" task in `dev.db`; `db:reset` and `db:seed` clean it (the seed is an upsert and does not delete it, so only `db:reset` does).
- **A handler mounted without `validate` still compiles.** `validOf` makes it fail loudly at runtime (a 500 and a clear log line), and there is no Bruno request for it because no real route is mounted that way.
- **The UTC instant is not range-checked.** See Decisions.
- **The request-ID middleware still validates `X-Request-Id` with a hand-written regex.** The brief's scope is body, params, query and the environment, so it was left. The grep in the brief's "no manual checks" criterion still lists it.
- **`API_KEY` and `DATABASE_URL` are checked with `.refine((x) => x.trim() !== '')`**, which the same grep also lists. It was kept so the value stays untrimmed, as in v2. Zod's `.trim().min(1)` would store the trimmed value.
- **`LOG_QUERIES` is `text === 'true'`**, not `z.stringbool()`, to keep v2's rule. `stringbool` is case-insensitive, accepts `1`, `yes`, `on` and rejects other text.
- **The `DATABASE_URL` message now starts with `Invalid environment:`**, like the other environment messages. v2's had no prefix.
- **A Zod issue can repeat for one field** (`priority: 1e300`). The error handler keeps the first message per path. If a future schema needs two messages for one field, the mapper hides one.
- **The comparison scripts are not committed.** They live in the scratchpad and in the guide (Stage 4). There is no regression test for the 4 `dueDate` differences beyond the Bruno requests. M09's tests are the place for one, and for the extra-field case `satisfies` cannot catch.
- **`z.iso.datetime` is Zod 4.6.7 behaviour** (seconds required unless `precision: -1`, hour 24 rejected). The `^4` range could take a minor version that changes it; `package-lock.json` pins 4.6.7.
- **`prisma/seed.ts` and `scripts/` read `DATABASE_URL` through `env.ts`, and `prisma7.config.ts` still reads it through Prisma's own `env()`.** Two readers of one variable. The Prisma CLI config cannot import `src/env.ts` without pulling the app into the CLI.

## [BACKLOG] Not verified

- **ISO 8601-1:2019's wording on `24:00:00`.** The standard itself was not read. The 1988 and 2000 editions allow it for midnight only (quoted in mailing-list posts), a source describing later guidance says interchange has no end-of-day form, and RFC 3339 sections 5.6 and 5.7 use hours 00 to 23 (read directly). The decision rests on RFC 3339 and on the README's silence, not on the 2019 text.
- **A learner following the guide cold.** The stages were run by the author in pieces and every code block and command was matched to the build, but nobody who did not build it followed it end to end.
- **Windows.** The guide's commands (`env -i`, `grep`, `curl`, `printf`, `pkill`) are for macOS and Linux and were only run on macOS (bash and zsh).
- **Other Node versions.** The `better-sqlite3` mismatch on Node 22 was seen, not fixed: it is the repo pinning Node 24, as `.nvmrc` says.
- **`z.toJSONSchema` and `zod/mini`** were each run once on a tiny schema. Neither was measured or used.

## [BACKLOG] Decisions made without the EM (EM-owned files, conventions)

- `tasks.md` is EM-authored. All 31 of its checkboxes are ticked, as in M05, M06 and M07, and nothing else in it changed. 27 were ticked while the build was done, and the last four ("Continue the branch → PR → merge habit", "v3 merged by pull request", "Final self-review against every Definition of done checkbox" and "Checkpoint evidence") after PR #8 was merged. The EM may prefer the file left untouched.
- **`z.guid()`, not `z.uuid()`, for `:id`.** v2 accepted any 8-4-4-4-12 hex id. `z.uuid()` turns some ids that were a 404 into a 400. The brief names `z.uuid()` as a format in its scope; it is taught and compared in Stage 2 and Stage 4. **Question for the EM:** is the intended contract "any well-formed id" or "a real UUID"? The ids this API makes are v4 and pass both.
- **The database settings are in a new `src/env.ts`, not `config.ts`.** The M07 backlog expected M08 to move them into `config.ts`. `config.ts` validates the whole environment when imported and needs `API_KEY`, and `db.ts` is imported by the seed script, so the seed would have stopped working without an `API_KEY`. The brief says "validate `process.env` once at startup in `config.ts`"; `config.ts` still does that for the server's settings.
- **Hour 24 is rejected and years 0000 to 0099 are accepted.** v2 did the opposite on both. The only written contract is the README's `dueDate` row ("ISO 8601 ... a date or a date-time, and the day must exist"); the briefs and PRD do not describe hours or years. The README now says "hour 00 to 23" and "four-digit year, 0000 to 9999". The M07 backlog's line that `T24:00:00Z` "is valid ISO 8601, so it is accepted" is now out of date. **Question for the EM:** is hour 24 meant to be accepted?
- **The four-digit year limit applies to the text sent, not to the stored instant.** A zone offset can move a date at the edge of the range outside it: `0000-01-01T00:00:00+23:59` is returned as `-000001-12-31T00:01:00.000Z`, and `9999-12-31T23:59:59-23:59` (v2 too) as `+010000-01-01T23:58:59.000Z`. The README says so and no code was changed. **Question for the EM:** should the contract reject an instant outside UTC years 0000 to 9999? If so it is a behaviour change at both ends and needs a Bruno request each.
- **No response schema.** The brief says to use Zod to shape responses and strip internal fields. The README documents `userId` as part of a task and Bruno asserts it, so there was nothing to strip.
- **Parsed data is on `res.locals.valid`**, read through `validOf`, not a typed `req.valid`, which would need a global Express type merge.
- **The parts of a request are checked in the order `:id`, body, query, and only the first failing part is reported**, as v2's handlers did. A request with a bad id and a bad body reports only the id.
- **The Bruno collection grew from 36 to 47 requests** (`Errors/25` to `28`, a `Dates/` folder of 7). The original 36 are unchanged. The M07 Definition of done said the M05 collection stays green; nothing in M08's brief limits adding to it.
- **The URL prefix stays `/api/v1`**, as in M07.
- **Unknown body keys are stripped**, not rejected, and v2's messages are kept through the `error` option.
- **The guide's Stage 4 (the v2 against v3 comparison) is not a brief task.** It is traced to the Definition of done ("a Zod schema rejects it first, every time") and labelled as the guide's own method. Stages 1, 8, 9 and 10 each contain items labelled "process check, not in the brief".
